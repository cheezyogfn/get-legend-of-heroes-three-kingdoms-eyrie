## 🔐 Keybinds That Do Not Conflict

Keybind collisions are the most common cause of "the module stopped working".

**Where collisions come from**

| **Source** | **Example** |
| --- | --- |
| Game defaults | `Insert`, `F1`–`F12`, `Home` |
| Other overlays | Steam, Discord, GPU drivers |
| Windows itself | `Win+G`, `Alt+Tab`, `Ctrl+Shift+Esc` |
| The tool's own modules | two modules on the same key |

**The rule that avoids all of it**

Pick a modifier-plus-key combination that no game uses: `Ctrl+Alt+` a function
key is almost always free. Single-key binds like `Insert` collide constantly
because games and overlays both claim them.

**Checking for a collision**

Press the bind with the game focused and nothing else running. If nothing
happens, the key is free. If something else happens, you have found the
collision before it costs you a session.

**One key per module**

A single panic key that disables everything sounds convenient and is not — it
removes your ability to drop one module while keeping another. Bind them
separately.

**What to do when a bind dies mid-session**

That usually means the game captured the key during a state change (menu,
cutscene, alt-tab). Rebind once; if it dies again on the same action, choose a
different combination rather than fighting it.
